# نشر روابط الدكتور إلى مجموعة استراحة أهل الأثر

## السلوك

- يستقبل البوت تحديثات Telegram الجديدة من المجموعة المحددة فقط.
- لا يعيد نشر الروابط إلا إذا كان مرسل الرسالة ضمن قائمة معرّفات الدكتور المسموح بها.
- يستخرج الروابط العادية وروابط النص المخفية (text links) من الرسائل والتعليقات على الوسائط.
- يمنع تكرار النشر عند إعادة Telegram إرسال webhook نفسه باستخدام سجل idempotency في Supabase.
- أمر المجموعة `/myid` يعرض رقم حساب المرسل لاستخدامه في قائمة السماح.
- من لوحة إدارة المحاضرات، زر «نشر روابط المحاضرات في مجموعة Telegram» يرسل روابط البث والتسجيل للمحاضرات المنشورة فقط. وعند حفظ محاضرة بحالة «منشورة» تُشغّل مزامنة الروابط تلقائيًا.

## أسرار Supabase Edge Function

اضبط القيم التالية في مشروع Supabase المستهدف (Preview أولًا):

- `TELEGRAM_BOT_TOKEN`: رمز البوت، كسرّ لا يظهر في Git أو المتصفح.
- `TELEGRAM_CHAT_ID`: معرّف مجموعة «استراحة أهل الأثر» (يجب أن يكون سالبًا للمجموعات الفائقة عادةً).
- `TELEGRAM_WEBHOOK_SECRET`: قيمة عشوائية قوية بطول 32 حرفًا على الأقل، بأحرف وأرقام وشرطة سفلية أو ناقص.
- `TELEGRAM_DOCTOR_USER_IDS`: معرّفات Telegram الرقمية للدكتور، مفصولة بفواصل. لا تستخدم أسماء المستخدمين لأنها قابلة للتغيير.
- `TELEGRAM_LINKS_ENABLED`: اجعله `true` بعد التحقق من المجموعة ومعرّفات الدكتور؛ اتركه غير مضبوط/false في Preview حتى لا يرسل إلى المجموعة الحقيقية.

تحتاج الدالة أيضًا إلى إعدادات Supabase المعتادة: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, و`SUPABASE_PUBLISHABLE_KEY` أو `SUPABASE_ANON_KEY`.

## إعداد webhook

بعد نشر الدالة وترحيل قاعدة البيانات، سجّل webhook من خلال Telegram Bot API إلى:

`https://hares.aboserag925.workers.dev/api/telegram/webhook`

وأرسل `secret_token` بالقيمة نفسها في `TELEGRAM_WEBHOOK_SECRET`. لا تضع الرمز في Git أو المحادثة. لا تسجل webhook على Preview مع مجموعة الإنتاج.

## خطوات التفعيل والتحقق

1. أضف البوت مشرفًا في مجموعة «استراحة أهل الأثر» مع صلاحية إرسال الرسائل وقراءة الرسائل الجديدة.
2. أرسل `/myid` من حساب الدكتور داخل المجموعة وسجّل الرقم الناتج في `TELEGRAM_DOCTOR_USER_IDS`.
3. انشر Edge Function وطبّق migration `20261119080000_telegram_link_deliveries.sql` على مشروع الاختبار أولًا.
4. اضبط أسرار Preview، ثم اختبر webhook برسالة رابط من حساب الدكتور، ورسالة رابط من عضو عادي (يجب تجاهلها)، وإعادة نفس update (يجب ألا تتكرر).
5. اختبر زر مزامنة روابط الموقع بحساب مشرف، وتأكد أن المسودات والأرشيف لا يُنشران.
6. لا تنقل الإعدادات إلى Production ولا تفعّل `TELEGRAM_LINKS_ENABLED=true` قبل موافقة صريحة واختبار المجموعة.

## حدود التنفيذ

- المزامنة الحالية تخص روابط البث والتسجيل المسجلة في جدول `lectures` وحالتها `published`.
- لا يستورد البوت تاريخ رسائل Telegram القديم تلقائيًا؛ webhook يستقبل التحديثات الجديدة بعد تسجيله. قراءة الأرشيف القديم تحتاج MTProto وحساب مستخدم منفصل.
- لا يتم إرسال أي رسالة إلى المجموعة من بيئة Preview.
